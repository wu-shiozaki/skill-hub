配布中のスキル

4件／更新 2026-09-16

Claudeチャット用 はclaude.ai・デスクトップアプリの「チャット」に入れるスキル、 Claude Code用 はClaude Codeに入れるスキルです。入れる場所が違います。 カードのラベルを確認してからダウンロードしてください。

アブソル

absol Claudeチャット用

翌日の商談を、前日の夜に下調べしておく。

前日18時に翌日の社外アポを見つけ、相手企業の下調べと課題仮説をカレンダーに置いておきます。朝には準備が終わっている状態になります。

スキル本体absol.zip マニュアル.md
できること・必要なもの
  • 社内定例を除いて、翌日の社外アポだけを自動で判別する
  • 企業情報・直近の動き・業界動向を調べて、要点だけにまとめる
  • 課題仮説を3案と、商談冒頭でそのまま投げられる問いを用意する
使う場所
Claudeチャット（claude.ai／デスクトップアプリ）
必要な接続
Googleカレンダーウェブ検索
動くタイミング
毎日18時の定期実行タスク／「アブソル呼んで」で手動実行も可
セットアップ
5〜10分（マニュアルをClaudeに読ませれば、ほぼ質問に答えるだけ）
向いている人
外部の商談が週に数件以上あり、事前準備の時間が取れていない人
入れたあとにやること
  1. Claudeの 設定 → コネクタ から、自分のアカウントでGoogleカレンダーを接続する
  2. ウェブ検索をオンにする
  3. SKILL.md の「利用者設定」で、自社メールドメインを自分の会社のものに直す
  4. 「アブソル呼んで」と送って、テスト実行する
  5. タスク機能で、平日18時に自動実行する設定を作る

マニュアルをClaudeに添付して「この通りにセットアップして」と送れば、 接続確認からテスト実行まで、Claudeが順番に進めてくれます。

安全のための設計
  1. 作成する予定に、相手のメールアドレス（ゲスト）は絶対に追加しません。課題仮説が相手に通知されるのを防ぐためです。
  2. 元の商談予定は編集も削除もせず、必ず別枠で新規作成します。
  3. 空き時間の扱いは「予定なし」で作るため、予約ツールの空き枠を塞ぎません。
  4. 書き出される課題仮説は公開情報からの推定です。商談で断定して話さないでください。

ネンドール

nendoll Claudeチャット用

商談のあとの3つの作業を、終わった順に片づける。

商談の議事録ができたら、お礼メールの下書き・管理表の更新・Slackへの速報までを自動でやります。メールは下書きのままです。

スキル本体nendoll.zip マニュアル.md
できること・必要なもの
  • 議事録から、話したこと・相手の反応・次アクションを拾って整理する
  • お礼メールの下書きをGmailに作る（送信はしない）
  • 商談管理表の行を更新し、チームへ結果を速報する
使う場所
Claudeチャット（claude.ai／デスクトップアプリ）
必要な接続
GoogleカレンダーGmailGoogleドライブSlack（任意）
動くタイミング
1時間おきの定期実行タスク／「ネンドール呼んで」で1件だけ手動実行も可
セットアップ
10分（管理表のURLとSlackチャンネルを決めておくとスムーズ）
前提
商談の議事録が自動で残っていること。議事録が無い商談は処理しません
向いている人
商談後のお礼メールと管理表の記入が、いつも後回しになっている人
入れたあとにやること
  1. 設定 → コネクタ から、自分のアカウントでカレンダー・Gmail・ドライブ・Slackを接続する
  2. SKILL.md の「利用者設定」に、自社ドメイン・管理表のURL・Slackチャンネル・署名を書く
  3. 商談の議事録がどこに残るかを決める（カレンダー添付が一番ラク）
  4. 「ネンドール呼んで」でテスト実行し、できた下書きを必ず自分で読む
  5. タスク機能で、平日9〜19時に1時間おきの自動実行を設定する

マニュアルをClaudeに添付して「この通りにセットアップして」と送れば、 接続の確認から管理表の列合わせまで、Claudeが順番に進めてくれます。

安全のための設計
  1. メールは下書きの作成までで、送信は絶対にしません。
  2. 社外に出るものはありません。速報はSlackの社内チャンネルだけです。
  3. 議事録に書かれていないことは書きません。推測で埋めません。
  4. 管理表の既存データは消さず、更新するのは段階・次アクション・商談日だけです。

ディアルガ

dialga Claude Code用

日程調整ページを、条件4つ言うだけで発行する。

条件を4つ答えるだけで、TimeRexの予約ページを作って予約URLを返します。受付時間や入力項目は、毎回同じ設定が自動で入ります。

スキル本体dialga.zip マニュアル.md
できること・必要なもの
  • タイトル・所要時間・参加メンバー・参加方式の4つを答えるだけで予約ページが完成する
  • 平日10-19時／Google Meet自動発行／直近14日／入力5項目すべて必須を、毎回もれなく適用する
  • 作ったあと公開ページを実際に開いて、土日に枠が出ていないかまで確認してから報告する
使う場所
Claude Code（zipを展開して ~/.claude/skills/ に置く）
必要な接続
Claude in ChromeTimeRexアカウントGoogleカレンダー連携（TimeRex側）
動くタイミング
定期実行なし／「ディアルガ呼んで」「TimeRex作って」で都度実行
セットアップ
5分（自分のTimeRexユーザー番号を調べて書き込むだけ）
前提
ChromeでTimeRexにログイン済みであること。ログイン操作はスキルではなく自分で行います
向いている人
商談ごとに日程調整ページを作っていて、毎回同じ設定を手で入れ直している人
入れたあとにやること
  1. zipを展開して ~/.claude/skills/dialga/SKILL.md になるように置く
  2. Chromeで https://timerex.net/ を開き、移動先URLの末尾の数字（自分のTimeRex番号）を控える
  3. SKILL.md の「利用者設定」に、その番号と自分のTimeRex表示名を書く
  4. ChromeでTimeRexにログインした状態にしておく
  5. 「ディアルガ呼んで。テスト用、30分、自分だけ」でテスト実行し、出てきたURLを自分で開いて確認する

マニュアルをClaude Codeに渡して「この通りにセットアップして」と送れば、 番号の調べ方からテスト実行まで、順番に進めてくれます。

安全のための設計
  1. TimeRexへのログインをしません。IDやパスワードは一切扱いません。
  2. 作るのは新規1本だけ。既存の予約ページや他の人のカレンダーは消しも触りもしません。
  3. チーム設定・会議室連携・アカウント設定は変更しません。
  4. 発行したURLをお客様に送りません。URLを返すところまでで、送るのは自分の手です。
  5. 予約URLを推測で作りません。TimeRexが発行した文字列をそのまま読み取って返します。

タブンネ

tabunne Claude Code用

商談が終わったら、管理表はもう埋まっている。

商談のカレンダー名を渡すだけで、議事録とWeb検索から会社情報・金額・次アクションまで拾って、商談管理表の1行を仕上げます。判断が入る4列は空けたまま残すので、自分で入れるのはそこだけです。

スキル本体tabunne.zip マニュアル.md
できること・必要なもの
  • カレンダーの予定名を渡すだけで、会社名・お名前・連絡先・商談日・議事録URLまで自動で埋まる
  • 議事録（Gemini によるメモ）から課題・反応・金額・次アクションを拾い、商談メモを1行にまとめる
  • HP・事業内容・創業年・住所など、カレンダーに無い会社情報はWeb検索で補う
  • 同じ会社の2回目以降は行を増やさず、初回→提案→クロと同じ行を育てる
使う場所
Claude Code（zipを展開して ~/.claude/skills/ に置く）
必要な接続
GoogleカレンダーGoogleドライブClaude in ChromeWeb検索
動くタイミング
「タブンネ呼んで」「管理表を埋めて」で都度実行／定期実行にして自動で回すことも可能
セットアップ
5分（商談管理表のURLと自分の名前を書き込むだけ）
前提
商談に「Gemini によるメモ」が生成されていること。無い商談は「議事録待ち」として飛ばします
向いている人
商談のあと、管理表への転記が後回しになって溜まっていく人
入れたあとにやること
  1. zipを展開して ~/.claude/skills/tabunne/SKILL.md になるように置く
  2. 商談管理表を開き、URLの /d/ と /edit の間のIDと、gid= の数字を控える
  3. SKILL.md の「初回設定」に、そのID・gid・自分のメールアドレス・管理表A列の担当名を書く
  4. 管理表のヘッダーの並びが、スキルの列マップ（A=担当／B=会社名…）と合っているか確認する
  5. 過去の商談のカレンダー名を貼ってテスト。書き込む前に確認が出るので、内容を見てからOKする

マニュアルをClaude Codeに渡して「この通りにセットアップして」と送れば、 IDの調べ方からテスト実行まで、順番に進めてくれます。

安全のための設計
  1. ステータス・申請予定コース・商材・ヨミ判断の4列には、空欄であっても書き込みません。判断は人がするものとして残します。
  2. A列の担当が自分以外の行には書き込みません。他の人の案件は読むだけです。
  3. 書き込む前に必ず内容を出して確認を取ります（自分で設定した自動実行時を除く）。
  4. 書いたあと必ず読み直し、触っていないはずの列が無傷かを検証してから完了と言います。
  5. 役職・人数・創業年・金額を推測で書きません。口頭の概算金額は金額欄に入れず、メモに事実として残します。
  6. メールの送信・下書き、Slackへの投稿、予定の変更、ファイルの削除は一切しません。

この種類のスキルはまだありません。
